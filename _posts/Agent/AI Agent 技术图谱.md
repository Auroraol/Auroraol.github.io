## AI Agent 技术图谱

 AI Agent的发展演进路线

agentic ai可以从横向和纵向两个方向思考：

纵向：Google提出的AI 5层能力

```
Level 0: Pre-trained LLM 本体，虽然基础，但是agentic AI推理能力的根本载体；
Level 1: 拥有历史问答的记忆 + 规划分析的能力 + 调用工具的能力（搜索引擎、各类互联网服务API、RAG知识库等）。本质特种是获得了与真实世界动态交互的能力。
Level 2: 拆解复杂问题为子问题，为解决子问题搜集所需要的资料、调用所需要的工具，合理分配关注子任务的“精力”，最终输出为统一且全面的答案。
Level 3: 多智能体系统，不同的智能体各司其职，共同达成更加复杂的任务目标。
Level 4: 自我学习自我成长，甚至可以根据需要创建新的智能体来满足任务需要
```

横向：Agent as 操作系统

```
计算核心（CPU）：LLM 本体
对话中上下文（RAM）：Context Window
长期记忆 （文件系统）：RAG
工具库 （软件应用）：LLM可以使用的terminal工具、查询天气预报的api，计算器api等等
互联网（浏览器）：根据任务需要联网搜索特定的信息 + 和其他的agent系统交互协作
```

##  AI Agent 工具链图谱

本图谱从底层模型到上层应用，系统梳理了构建现代 AI Agent 所需的全套技术栈，重点强化了逻辑推理、数据编排、生产级部署与专业评估体系。

### 基础层：智能体的"大脑" (LLM)

基础层是智能体的推理核心。在选择模型时，不仅要看参数量，更要关注代码能力、指令遵循（Instruction Following）和上下文窗口。

| 模型名称          | 核心特点                         | 适用场景                           | 技术优势                                                    |
| ----------------- | -------------------------------- | ---------------------------------- | ----------------------------------------------------------- |
| Claude 3.5 Sonnet | 代码与逻辑推理最强，极低的幻觉率 | 复杂编程任务、Agent 规划、工具调用 | 在 Coding 和复杂逻辑基准测试中经常霸榜，指令遵循度极高      |
| GPT-4o            | 综合能力均衡，多模态实时交互     | 语音实时交互、通用高难度任务       | 工业界标准，Function Calling 调优最佳，API 极度稳定         |
| Qwen (通义千问)   | 中文理解突出，开源生态活跃       | 中文内容创作、本地化应用开发       | 涵盖 7B 到 72B 多版本，Qwen2.5 编码能力大幅提升             |
| Deepseek          | 性价比之王，推理效率极高         | 边缘计算、高频低成本调用场景       | 混合专家系统 (MoE) 架构，在极低成本下实现接近顶尖模型的性能 |
| Llama 3.1/3.2     | 开源界最强基座，支持微调         | 私有化部署、数据隐私敏感行业       | 生态最丰富，便于进行 SFT (监督微调) 适配特定垂类任务        |
| Gemini 1.5 Pro    | 超长上下文 (2M+)，原生多模态     | 长视频分析、海量代码库理解         | 与 Google 生态集成，能够处理极大吞吐量的多模态输入          |
| Kimi (Moonshot)   | 长文本处理专精                   | 法律合同审查、长文档研报分析       | 缓存机制优化，长文本下的“大海捞针”能力强                    |

### 记忆与数据层：智能体的"海马体"

除了传统的向量数据库，图数据库正在成为 RAG（检索增强生成）向 GraphRAG 进化的关键，用于解决复杂的关系推理问题。

向量数据库 (Vector DB)

| 数据库   | 核心特点                   | 适用场景                           |
| -------- | -------------------------- | ---------------------------------- |
| Milvus   | 开源高性能，支持分布式部署 | 企业级大规模知识库 (十亿级向量)    |
| Chroma   | 轻量级，开发体验极佳       | 个人项目、快速原型、Python 环境    |
| Pinecone | 云原生 SaaS，全托管        | 海外业务、无需运维的生产环境       |
| Weaviate | 混合搜索能力强             | 需要同时进行关键词和向量检索的场景 |

 图数据库 (Graph DB) - GraphRAG 核心

| 数据库      | 核心特点                 | 适用场景                                |
| ----------- | ------------------------ | --------------------------------------- |
| Neo4j       | 市场占有率最高，生态完善 | 构建知识图谱，结合 LLM 进行深度关系挖掘 |
| NebulaGraph | 高性能分布式图数据库     | 处理海量关联数据，如金融风控、社交网络  |

### 架构与编排层：智能体的"骨架"

这一层决定了 Agent 如何思考、规划和处理数据。

提示词工程策略（Prompting Strategy）或智能体认知模式（Cognitive Architecture）

| 模式名称               | 核心逻辑                            | 适用场景                     | 优缺点                                                     |
| ---------------------- | ----------------------------------- | ---------------------------- | ---------------------------------------------------------- |
| ReAct (Reason+Act)     | 思考-行动-观察循环                  | 需要调用工具解决问题的场景   | 最经典模式。能纠正事实错误，但步骤多时容易陷入死循环       |
| CoT (Chain of Thought) | 分步推理 (Let's think step by step) | 纯逻辑推理、数学问题         | 提升推理准确性，但不涉及外部工具调用                       |
| ToT (Tree of Thoughts) | 思维树搜索 (DFS/BFS)                | 极复杂的规划、解谜、创意写作 | 探索多种可能性，效果好但Token消耗巨大                      |
| Reflexion              | 反思与自我修正                      | 需要高质量输出、代码纠错     | 引入"语言反馈"，通过自我批评优化下一次执行，极大提升成功率 |
| Plan-and-Solve         | 先规划后执行                        | 步骤繁琐的长期任务           | 避免像 ReAct 那样走一步看一步，宏观把控能力更强            |

实现strategy的工具：

| 框架名称   | 核心定位                      | 适用场景                           | 技术优势                                              |
| ---------- | ----------------------------- | ---------------------------------- | ----------------------------------------------------- |
| LangChain  | 通用胶水层                    | 快速原型开发、基础 Agent 构建      | 社区最大，组件最全，几乎支持所有模型和工具            |
| LlamaIndex | 数据中心化框架 (Data-Centric) | 构建高质量 RAG 系统、文档分析      | 专注解决 Context 处理，提供高级索引策略（如递归检索） |
| LangGraph  | 有环图结构编排                | 复杂状态管理、循环任务、多步推理   | 允许构建循环 (Loops)，比线性链更适合复杂 Agent 逻辑   |
| DSPy       | 编程化提示词 (Prompt as Code) | 追求高稳定性、需要自动迭代的 Agent | 将 Prompt 视为参数进行自动优化（编译），代替手动调优  |
| AutoGen    | 多智能体协作 (Multi-Agent)    | 复杂任务分工、代码生成与执行       | 微软出品，强大的会话模式，支持 Agent 间的自动对话     |
| CrewAI     | 角色扮演协作框架              | 业务流程自动化                     | 基于角色的设计 (Role-based)，易于模拟人类团队分工     |

### 交互与工具层：智能体的"感官与手脚"

Agent 通过标准化协议与外部世界交互。

####  工具调用协议

| 协议名称                     | 核心特点                    | 适用场景                           |
| ---------------------------- | --------------------------- | ---------------------------------- |
| MCP (Model Context Protocol) | Anthropic 推出的开放标准    | 跨模型工具调用，致力于打破生态壁垒 |
| Function Calling             | OpenAI 定义的 JSON 交互标准 | 目前最主流的工具调用方式，精准度高 |

####  执行工具

通用类： 浏览器自动化 (Selenium/Playwright)、代码解释器 (Code Interpreter/SandBox)、API 连接器。

垂类专用：

金融： Alpha Vantage, Bloomberg Terminal API

法律： LexisNexis 接口

办公： Microsoft Graph API (操作 Office 365)

### 低代码开发平台：快速构建

让非技术人员也能构建 Agent 应用。

| 平台        | 核心特点                     | 适用场景                                       |
| ----------- | ---------------------------- | ---------------------------------------------- |
| Dify        | 开源、涵盖 RAG 与 Agent 编排 | 企业内部知识库、对外客服机器人，支持模型非常全 |
| Coze (扣子) | 字节跳动出品，插件生态丰富   | 快速构建发布到微信/飞书/Discord 的 Bot         |
| Flowise     | 基于 LangChain 的拖拽式 UI   | 学习 LangChain 逻辑，快速搭建原型              |

低代码/无代码平台本质上是 Agentic AI 技术栈的操作系统（OS）。它们不生产模型或算法，而是通过封装和编排，将前面章节提到的所有底层技术组件集成在一个可视化的控制台中。

 1. 它们是如何关系的？(The Relationship)

如果把 AI Agent 比作一台精密的机器：

基础层 (LLM) 是发动机。

架构层 (LangChain) 是传动系统。

工具层 (Tools) 是轮子和机械臂。

低代码平台 (Dify/Coze) 就是驾驶舱和仪表盘。它屏蔽了底层代码的复杂性（如 Python 依赖管理、API 对接、向量切片），让用户通过图形界面直接操控这些核心组件。

 2. 具体集成了哪些技术？(Integration Matrix)

这些平台通常通过以下方式“吞噬”并集成底层技术栈：

| 技术层级 (来自前文) | 平台集成的具体方式                                           | 例子 (以 Dify/Flowise 为例)                                  |
| ------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 基础层 (LLM)        | API 网关化。平台预置了 OpenAI、Claude、Qwen 等数十种模型的 API 接口，用户只需填入 Key 即可切换大脑，无需写代码适配 SDK。 | Dify 的"模型供应商"设置页直接集成了 Bedrock、Ollama 和 HuggingFace。 |
| 记忆层 (RAG)        | ETL 流程自动化。平台内置了非结构化数据解析（Unstructured）、切片（Chunking）和向量化流程。它们通常内置了 Chroma/Qdrant 或连接外部 Milvus。 | 上传 PDF，平台自动完成清洗、分段、Embedding 并存入内置的 Weaviate/PGVector 中。 |
| 架构层 (编排)       | 可视化组件化。将 LangChain 的 "Chain" 或 "ReAct Agent" 封装成可拖拽的节点。 | Flowise 的每一个节点（如 "Conversational Retrieval Chain"）都直接对应 LangChain JS 的一个类。 |
| 工具层 (Tools)      | 标准化接口 (OpenAPI)。支持直接导入 OpenAPI (Swagger) 规范，自动把外部 API 转化为 Agent 可调用的“技能”。 | 在 Coze 中输入一个天气 API 的 URL，它自动解析参数并生成 Tool，供 Agent 决策时调用。 |
| 认知模式 (Patterns) | 预设工作流模板。平台将 CoT、ReAct 等复杂提示词策略固化为“系统提示词”或“工作流节点”。 | Dify 的 "Agent 模式" 默认开启了 Function Calling 循环（ReAct 变体），用户无需手动编写 Loop 逻辑。 |

 3. 如何实现集成？(How to Integrate)

在实际操作中，集成通常分为三个深度的层次：

配置级集成 (Configuration)：

操作： 在平台后台填入 OpenAI API Key、AWS 密钥或向量数据库的 URL。

效果： 平台接管底层的连接工作。

协议级集成 (Protocol)：

操作： 导入 OpenAPI JSON 文件或绑定 OAuth 鉴权。

效果： 平台让 Agent 能够“理解”并操作你的内部 ERP、飞书表格或数据库。

代码级集成 (Code Injection)：

操作： 在平台的“自定义代码节点”中编写 Python/Node.js 脚本。

效果： 弥补平台预设功能的不足，处理特殊的数学计算或数据转换逻辑
